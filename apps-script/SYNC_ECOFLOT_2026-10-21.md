# ECOFLOT — установка обновления защиты от дублей в действующий Apps Script

> **ВАЖНО:** Коммит GitHub — не развёртывание Google Apps Script.
> Выполнять только в **существующем** проекте из Google Sheets «ECOFLOT Заявки».
> Сохранять текущий `/exec`, токены, очередь, триггеры и прочие `.gs` без замены.

## Предварительная проверка

1. Откройте [Google Sheets «ECOFLOT Заявки»](https://docs.google.com/spreadsheets/d/1wQQhP81P_07QkAGB5KzI20w9PBqN55y9pUs6WUnA8Ws/edit).
2. **Расширения → Apps Script**: убедитесь, что проект содержит `findDuplicate_`, `handleLead_`, `processTelegramOutbox`. Если имена и интеграция отличаются, **остановитесь**, сохраните копию текста функции и проверьте адаптацию прежде чем изменять.
3. В **Управление развертываниями** запишите номер текущей версии Web app. Не удаляйте существующее развёртывание.
4. Резервная копия: скопируйте содержимое редактируемого `.gs` в личный файл. **Не передавайте секреты/токены в чат.**

## Точечные изменения для ECOFLOT server v5.1

1. В существующем Apps Script создайте `ecoflot_server_guards.gs` или **обновите содержимое файла с таким именем** кодом из
   [apps-script/ecoflot_server_guards.gs](https://github.com/Ivankorytnik/ECOFLOT/blob/main/apps-script/ecoflot_server_guards.gs).
   Не заменяйте весь `Code.gs`. В одном проекте функции `ecoflot*V3_` должны быть определены **один раз**.
2. В рабочей функции `findDuplicate_(sheet, headers, lead)` **сохраните её существующее тело** и вставьте следующие две строки **после** проверки идентичного Request ID и после раннего `return null` для форм **собственного сайта** (перед старой проверкой ссылки):
```javascript
  var identityMatch = ecoflotFindDuplicateV3_(sheet, headers, lead);
  if (identityMatch) return identityMatch;
```
   Нельзя добавлять этот вызов до защитного условия для обычных заявок с сайта.
   **Не используйте** файл `REPLACE_findDuplicate.gs` как замену `findDuplicate_` для v5.1: старый `ecoflotSelfTest()` ожидает сохранённую проверку `ef5Procurement_`.
3. Сохраните. В списке функций выберите `ecoflotGuardSelfTest20261021_` → **Выполнить**. Результат должен иметь `ok:true`, все 6 тестов `ok:true`, `readOnly:true`. Функция не отправляет запросов и не трогает таблицу.
4. Если установлен сервер v5.1, запустите старую `ecoflotSelfTest`. Не публикуйте, если какая-либо проверка упала.
5. **Развернуть → Управление развертываниями → ✎ у существующего Web app → Версия: новая → Развернуть**. Не создавайте новый Web app, URL `/exec` должен остаться прежним.
6. Сохраните номер новой версии и время; убедитесь, что входящие заявки продолжают попадать в таблицу и очередь и Telegram остаётся работоспособным. Проведите контрольный прогон с защитой от дублей; не отправляйте искусственные заказы в CRM.

## Чего не делать

- Не заменять `Code.gs` старым `ECOFLOT_Code_READY.txt` — это архив на 7 октября и он может стереть последующие изменения.
- Не запускать `installTriggers()` повторно и не менять Telegram webhook, URL Web app, свойства проекта и список получателей.
- Не удалять исторические строки или старые сообщения; обнаруженные дубликаты в CRM устранять отдельно после резервной копии и сверки статусов.

## Если из ChatGPT невозможно редактировать Apps Script

Доступ к Google Drive/Sheets **не** даёт право редактировать опубликованный Apps Script через интеграцию Drive. Для прямой публикации нужен отдельный доступ через **Google Apps Script API с OAuth** (или авторизованный браузер в ChatGPT Work). Нельзя считать GitHub merged/deployed доказательством обновления GAS.

Исправляемая публикация в GitHub: PR #21 (коммит `03a891fe05643430c8477621247e60c1aff3d202`).
